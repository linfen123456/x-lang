# 性能设计与可测目标

> 状态：Accepted｜版本：2.1.0｜负责人：Perf Lead｜最后更新：2026-10-22
> 类型：Performance｜唯一负责：性能目标、基准集合、测量方法、回归阈值。所有数值都是**目标**，P1 采集基线后经 ADR 校准一次；除标注【推断】的初值外，不引用未经验证的外部数据。

## 1. 结论

1. 性能只用**同算法、同机器、同测量方法**的相对指标来承诺。主参照是 C（clang -O2），辅参照是 Rust（release）。
2. 1.0 运行时目标：基准集几何平均 ≤ 1.25 倍 C；任何单项 ≤ 2 倍。
3. 编译器目标覆盖：全量检查吞吐、增量响应、LSP 延迟、峰值内存。
4. 原始文档 12.txt 中的绝对数值承诺（如“< 1ns”）全部改写为 §6 中的可测目标或指向生态包的基准。

## 2. 测量方法（强制）

1. 硬件：专用基准机，Linux x86_64，关闭 CPU 频率调节与 SMT，在固定核心上运行。规格写入 `bench/MACHINE.md`。Windows x86_64 是第二基准机（P2 起，同一台硬件双系统或同规格机器），macOS arm64 是第三基准机（P3 起）。
2. 每项重复运行 ≥ 10 次，报告中位数与 95% 置信区间；只有差异超出置信区间才判定为回归。
3. 工具：`x test --bench`（P2）；外部计时用 `hyperfine` 类工具；编译器自身使用 `x build --timings`。
4. 结果以 JSON 格式存档（提交哈希、机器、工具链版本、原始样本），保存在 `bench/results/`，每夜更新。
5. 回归阈值：同一基准相对上一个发布版本变慢 > 5% 时，阻断发布；变慢 > 3% 时，自动建 Issue。

## 3. 基准集合 `xbench`

| 类别 | 基准 | 对照实现 |
|---|---|---|
| 计算 | binary-trees、fannkuch-redux、n-body、spectral-norm、mandelbrot | C、Rust（Benchmarks Game 公开算法） |
| 内存/集合 | Vec push/pop、HashMap 插入/查找 1M、BTreeMap、字符串拼接 | C（手写）、Rust std |
| 文本/I/O | `xwc` 与 `xgrep`（参考 CLI）处理 1 GiB 文件 | GNU `wc`/`grep -F` |
| 并发 | 通道吞吐（SPSC/MPMC）、Mutex 争用、作用域线程并行求和 | C pthread、Rust std |
| 编译器 | 生成式语料（10k、100k 行）、std 自身 | 自身历史值 |

## 4. 安全检查的成本控制

1. 整数溢出检查在所有 Profile 中开启（[ADR-0007](decisions/ADR-0007-language-core-decisions.md) D18）。成本的测法：同一基准分别使用默认算术与 `wrapping_*` 版本，比较两者差距。
2. 目标：1.0 时溢出检查开销的几何平均 ≤ 5%，单项 ≤ 15%。手段包括 LLVM 溢出内建、区间分析消除检查、循环归纳变量证明。
3. 越界检查采用同样方法，目标相同。
4. 如果 P2 实测几何平均开销 > 10%，必须提交 ADR，在“优化投入”与“新增 Profile 级开关”之间做决定（默认维持开启）。

## 5. 目标表

| 指标 | P1（只记录） | P2（MVP 门禁） | 1.0（P4 门禁） |
|---|---|---|---|
| 运行时几何平均（相对 C -O2） | 记录 | ≤ 1.5 倍 | ≤ 1.25 倍 |
| 运行时单项最差 | 记录 | ≤ 3 倍 | ≤ 2 倍 |
| `xwc`/`xgrep` 吞吐（相对 GNU 工具） | 记录 | ≥ 0.7 倍 | ≥ 0.9 倍 |
| `x check` 全量，100k 行【推断】 | 记录 | ≤ 10 s | ≤ 5 s |
| 增量：修改单个函数体后 `x check`（100k 行） | 记录 | ≤ 1 s | ≤ 300 ms |
| `x build` dev，Hello World | ≤ 2 s | ≤ 1 s | ≤ 0.5 s |
| LSP 补全 / 悬停 p95 | — | — | ≤ 100 ms |
| 编译器峰值 RSS，100k 行 | 记录 | ≤ 3 GiB | ≤ 2 GiB |
| Hello 二进制体积（release，stripped，静态链接 xrt） | 记录 | ≤ 1 MiB | ≤ 500 KiB |
| 进程启动至 `main`（Linux） | 记录 | ≤ 5 ms | ≤ 2 ms |

【推断】标注的数值是起草时的估计，P1 结束时按实测基线校准一次。校准只能放宽或收紧一次，必须记录在 ADR 中。

## 6. 原始性能承诺（12.txt）的改写

| 原始承诺 | 问题 | 改写后的可测目标 | 落点 |
|---|---|---|---|
| 非内联函数调用 < 1ns | 与硬件强相关；“尾调用优化”与非内联调用的开销无关 | 调用开销微基准与 C 同签名函数相差 ≤ 10% | `xbench` 微基准（P2） |
| 协程切换 ~20ns | 1.0 没有协程 | async 引入时（P5）与 Rust tokio、Go 同场景对比 | P5 RFC |
| 跨进程共享内存消息 ~50ns | 由生态包实现 | `x-ipc` 的 SPSC Ring 往返延迟与 C 实现相差 ≤ 10% | `x-ipc` 基准（P4） |
| 4K 随机读 ~10µs | 取决于设备 | `std::fs` 读取吞吐与 C `pread` 相差 ≤ 5%；io_uring 由 P5 适配器提供 | P2 / P5 |
| JSON 解析 ~1.2 GB/s | 取决于数据与 SIMD | `x-json` 在公开语料（如 twitter.json、canada.json）上与一种 C/Rust 参考实现对比，P3 只记录，P4 达到 ≥ 0.5 倍 | `x-json` 基准 |
| P99.9 抖动 < ±50µs | 取决于 OS 与调度 | 提供 OS 实时优先级 API 封装；抖动由应用自行测量，不做语言层承诺 | `x-sched`（P4） |
| `likely` 使命中率达到 99.9% | 无法由编译器保证 | `core::hint::likely/unlikely` 只影响代码布局，不承诺命中率 | std（P2） |
| 无异常模式达到“纯 C 速度的 100%” | 无法验证 | `panic=abort` 下无 unwind 表；开销计入 §5 运行时目标 | P0 起 |
| 1 GiB Parquet < 500ms | 取决于数据与硬件 | `x-arrow` 绑定成熟实现，不做独立承诺 | P5 生态 |
