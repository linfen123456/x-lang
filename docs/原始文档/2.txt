## 二、编译器核心架构

### 2.1 整体编译流程

X编译器采用**三段式架构**，参考了Rustc和Go编译器的设计经验：

| 阶段 | 模块 | 输入 | 输出 | 职责 |
|------|------|------|------|------|
| **前端** | Lexer | `.x`源码 | Token流 | 词法分析 |
| | Parser | Token流 | AST | 语法分析，构建抽象语法树 |
| | Semantic Analyzer | AST | 带类型标注的AST | 类型检查、名称解析、借用检查 |
| **中端** | HIR Generator | 类型化AST | HIR | 高级中间表示（保留语义信息） |
| | Optimizer | HIR | 优化后的HIR | 平台无关优化（常量折叠、死代码消除等） |
| | LIR Generator | HIR | LIR (LLVM IR) | 降级为低级中间表示 |
| **后端** | LLVM Backend | LLVM IR | 原生机器码 | x86_64/ARM64/等 |
| | WASM Backend | LLVM IR | WebAssembly | 浏览器/边缘计算 |
| | 交叉编译 | LLVM IR | 平台目标码 | Android/iOS/等 |

### 2.2 编译器模块划分（Rust实现）

编译器使用 **Rust** 开发，模块结构如下：

```
x-compiler/
├── Cargo.toml
├── src/
│   ├── bin/
│   │   └── xc.rs              # 编译器主入口 (x compile)
│   ├── lexer/                 # 词法分析
│   │   ├── mod.rs
│   │   ├── token.rs           # Token定义
│   │   └── lexer.rs           # 词法分析器实现
│   ├── parser/                # 语法分析
│   │   ├── mod.rs
│   │   ├── ast.rs             # AST节点定义
│   │   └── parser.rs          # 递归下降/Pratt解析器
│   ├── semantic/              # 语义分析
│   │   ├── mod.rs
│   │   ├── type_checker.rs    # 类型检查
│   │   ├── borrow_checker.rs  # 借用检查（所有权系统）
│   │   └── resolver.rs        # 名称解析
│   ├── hir/                   # 高级中间表示
│   │   ├── mod.rs
│   │   └── hir.rs             # HIR数据结构
│   ├── lir/                   # 低级中间表示
│   │   ├── mod.rs
│   │   └── gen_llvm.rs        # LLVM IR生成
│   ├── backend/               # 后端
│   │   ├── mod.rs
│   │   ├── llvm.rs            # LLVM封装
│   │   └── wasm.rs            # WASM后端
│   ├── codegen/               # 代码生成
│   │   ├── mod.rs
│   │   └── optimizer.rs       # 优化管道
│   └── util/                  # 工具函数
│       ├── mod.rs
│       └── diagnostics.rs     # 错误报告（彩色、带位置）
├── tests/                     # 编译器测试
└── examples/                  # 示例程序
```

### 2.3 关键设计决策

1. **自举（Bootstrapping）** ：编译器初期用Rust实现，稳定后用X语言重写
2. **增量编译**：基于文件依赖图，只重新编译变更部分
3. **并行编译**：利用Rust的`rayon`实现crate级别的并行编译
4. **错误诊断**：参考Rust的彩色、带代码位置、带建议的错误报告

## 三、语言服务器协议（LSP）实现

### 3.1 架构设计

LSP服务器采用 **Rust + tower-lsp** 实现，为VS Code、IntelliJ等所有支持LSP的编辑器提供语言服务：

```
┌─────────────────────────────────────────────────────┐
│                   LSP Server                        │
│  ┌─────────────────────────────────────────────┐   │
│  │         LanguageServer Trait                │   │
│  │  - initialize()    - shutdown()             │   │
│  │  - did_open()      - did_change()           │   │
│  │  - did_close()     - completion()           │   │
│  │  - goto_definition() - hover()              │   │
│  │  - references()    - rename()               │   │
│  │  - formatting()    - code_action()          │   │
│  └─────────────────────────────────────────────┘   │
│                         │                           │
│  ┌──────────────────────▼──────────────────────┐   │
│  │           X Language Core                   │   │
│  │  - AST (基于tree-sitter)       │   │
│  │  - 符号表 (Symbol Table)                    │   │
│  │  - 类型信息 (Type Info)                     │   │
│  │  - 文档索引 (Document Index)                │   │
│  └─────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
```

### 3.2 LSP服务器模块结构

```
x-lsp/
├── Cargo.toml
├── src/
│   ├── main.rs              # LSP服务器入口
│   ├── server.rs            # LanguageServer trait实现
│   ├── analysis/            # 代码分析
│   │   ├── mod.rs
│   │   ├── symbol.rs        # 符号查找
│   │   ├── reference.rs     # 引用查找
│   │   └── type_info.rs     # 类型信息
│   ├── completion/          # 自动补全
│   │   ├── mod.rs
│   │   └── provider.rs      # 补全项提供者
│   ├── navigation/          # 代码导航
│   │   ├── mod.rs
│   │   ├── definition.rs    # 跳转到定义
│   │   └── hover.rs         # 悬停提示
│   ├── formatting/          # 代码格式化
│   │   ├── mod.rs
│   │   └── formatter.rs     # 基于AST的格式化
│   └── diagnostics/         # 诊断信息
│       ├── mod.rs
│       └── checker.rs       # 实时错误检查
└── tests/                   # LSP测试
```

### 3.3 LSP实现要点

- **tree-sitter集成**：使用tree-sitter提供高性能的增量解析
- **增量更新**：文档变更时只重新解析变更部分
- **缓存机制**：符号表、类型信息在内存中缓存，提高响应速度

```
└── 11-ffi.md                # 外部函数接口
```

### 6.2 核心语法示例（草案）

```
// X语言语法示例

// 1. 变量声明（默认不可变）
let x: i32 = 42
let mut y: f64 = 3.14    // mut表示可变

// 2. 函数定义
fn add(a: i32, b: i32) -> i32 {
    return a + b
    // 或: a + b  (尾表达式)
}

// 3. 所有权与借用
fn process(data: &[u8]) -> i32 {  // & 表示借用
    // ...
}

// 4. 结构体
struct Point {
    x: f64,
    y: f64,
}

// 5. 方法
impl Point {
    fn distance(&self) -> f64 {
        (self.x * self.x + self.y * self.y).sqrt()
    }
}

// 6. 并发（协程）
spawn fn() {
    // 并发执行
}

// 7. Channel通信
let ch = channel<i32>()
ch.send(42)
let val = ch.recv()

// 8. 泛型
fn identity<T>(x: T) -> T {
    return x
}

// 9. 模式匹配
match value {
    0 => "zero",
    1 => "one",
    _ => "other",
}

// 10. 接口（trait）
trait Printable {
    fn print(&self)
}
```

### 6.3 语法设计原则

1. **显式优于隐式**：类型、可变性、所有权都显式标注
2. **无歧义**：语法规则清晰，避免C++式的多重解析
3. **渐进式学习**：核心语法简单，高级特性按需使用
4. **一致性**：相似概念使用相似语法

## 九、技术选型总结

| 组件 | 技术选型 | 理由 |
|------|---------|------|
| **编译器** | Rust + LLVM | 性能、安全性、LLVM生态成熟 |
| **LSP服务器** | Rust + tower-lsp | 高性能、与编译器共享代码 |
| **VS Code插件** | TypeScript | 官方推荐、生态完善 |
| **IntelliJ插件** | Kotlin + Grammar-Kit | JetBrains官方方案 |
| **语法解析** | 手写递归下降 + Pratt | 更好的错误恢复和诊断 |
| **中间表示** | LLVM IR + 自定义HIR | 平台无关优化 + 多后端支持 |
| **包管理器** | Rust + TOML | 参考Cargo设计 |
| **测试** | Rust原生测试框架 | 集成方便 |

这套架构方案涵盖了从编译器核心到IDE集成的完整链路，可以作为X语言项目的实施蓝图。如有具体模块需要进一步展开，可以继续深入讨论。
