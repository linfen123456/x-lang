## 0. 实施规则与完成定义

### 0.1 工程目标

本大纲将 `docs/原始文档/1.txt` 至 `12.txt` 中的实现设想组织为一条不被远期特性阻塞的工程主线：先冻结最小规范并验证端到端编译，再完善核心语言、标准库和工具链，最后按 RFC 引入扩展和研究后端。本文只定义工作包、接口边界、交付物和验收，不替代详细设计、ADR、威胁模型或测试方案。

### 0.2 默认架构决策

| 决策 | 当前状态 | 实施约束 |
|---|---|---|
| 初始编译器使用 Rust | `已决策` | 自举安排在 1.0 后，不能阻塞早期版本。 |
| 首个原生后端使用 LLVM | `已决策` | 通过后端接口隔离 LLVM，不让其类型泄漏到前端。 |
| 使用自定义 AST/HIR/MIR | `已决策` | 每层有版本化内部契约、验证器和文本打印格式。 |
| 所有权 + 借用 + RAII | `已决策` | 核心安全模型；可选 GC 仅做隔离实验。 |
| 首批目标集合 | `已决策` | Windows/Linux/macOS 的 x86_64/ARM64 均纳入路线；Stable 支持级别按真实 CI、真机和发布能力逐目标晋级，不要求六个组合同时成为 Tier 1。 |
| WASM 及其他后端 | `待阶段实施` | WASM 在核心稳定后；GPU/eBPF/裸机/移动端均需独立 RFC。 |

重大架构选择必须写入 `docs/decisions/` 的 ADR；未形成 ADR 的方案不得被视为永久约束。

### 0.3 任务卡完成定义

每个实施任务必须包含：负责人角色、范围与非范围、规范依据、输入输出接口、依赖、预计规模、实现步骤、测试、性能/安全要求、文档更新、回滚方案和验收证据。只有代码评审、自动化测试、文档和追溯同时完成，任务才能关闭。

### 0.4 成熟度和质量门禁

沿用配套规范的 `CORE / EXTENDED / EXPERIMENTAL / RESEARCH` 分级。实验能力必须默认关闭、不得改变稳定语义、不得进入 1.0 兼容承诺。任何性能目标必须给出可复现基准；任何“安全”声明必须对应威胁模型、静态规则、运行时检查或测试证据。

### 0.5 工程完整性基线

本文描述阶段和工作包，[完整项目目录架构与模块说明](./X-Lang完整项目目录架构与模块说明.md)是建仓、模块边界和项目内容的权威蓝图，[原始功能全量追溯矩阵](./X-Lang原始功能全量追溯矩阵.md)是范围完整性的权威清单。任何任务必须同时引用 `XLF-*`、规范/RFC/ADR、目标子项目和测试；仅写“来源：N”或仅列顶层目录不能关闭任务。

### 0.6 后续工程专题展开方式

当前只保留本工程大纲，原编译器、运行时、工具链、测试、CI、发布、运维和任务 DAG 专题正文已移除。后续实施时按本大纲的篇章和工作包逐项生成必要专题；每份专题必须回链原始功能矩阵、完整项目目录架构、目标子项目和验收测试，不复制本文件已有目录说明。

## 第四篇 编译器前端实施

**输出物**：前端 crate、AST/HIR、诊断、语法和语义测试套件。  
**验收标准**：每阶段都有验证器；恶意/错误输入不崩溃；规范测试全部映射。

| 编号 | 工作包 | 分级/状态 | 实施内容 | 交付与验收 |

| 4.2 | Token 与 Lexer | `CORE/草案` | TokenKind、Trivia、字面量、错误 Token、迭代接口和零复制切片策略。 | 词法符合性、属性测试和 fuzz 无崩溃。 |
| 4.3 | Parser 与恢复 | `CORE/草案` | 递归下降 + Pratt、同步点、缺失节点、错误抑制和恢复成本。来源：2。 | 合法语料 AST 匹配；错误输入产生有限且稳定诊断。 |
| 4.4 | AST 基础设施 | `CORE/草案` | 节点、NodeId、Span、Visitor/Folder、pretty printer 和结构快照。 | parse-print-parse 保持等价；AST 验证器通过。 |
| 4.5 | 名称解析 | `CORE/草案` | DefId、作用域、模块、导入、可见性、重复定义和循环。 | 解析表可 dump；边界用例和增量稳定 ID 测试。 |

## 第五篇 中间表示与优化

**章节目标**：通过分层 IR 保存必要语义、实现可验证降级并承载优化。  
**输入与依赖**：类型化 AST/HIR、后端接口。  
**输出物**：HIR/MIR 数据结构、构建器、验证器、Pass 框架、快照测试。  
**验收标准**：每次变换前后不变量明确；优化可关闭；错误可定位到源码。

| 编号 | 工作包 | 分级/状态 | 实施内容 | 交付与验收 |
|---|---|---|---|---|
| 5.1 | AST→HIR | `CORE/草案` | 名称绑定、类型、语法糖脱糖、模式展开和稳定 DefId。 | HIR 文本快照；来源 Span 可回溯。 |
| 5.2 | HIR→MIR/LIR | `CORE/草案` | 基本块、Place、Operand、Rvalue、Terminator、显式 Drop 和控制流。 | MIR 验证器检查类型、支配和终结。 |
| 5.3 | CFG/SSA/数据流 | `CORE/草案` | CFG、支配树、活跃性、到达定义；是否采用全 SSA 通过 ADR 决定。 | 用小型 IR 单元测试验证算法和异常 CFG。 |
| 5.4 | 基础优化 | `CORE/草案` | 常量折叠、简化 CFG、死代码、拷贝传播和安全内联。来源：1、2。 | `-O0` 语义基线；差分测试证明优化等价。 |
| 5.5 | 高级脱糖 | `CORE+EXTENDED/待决策` | 泛型单态化、闭包环境、async 状态机、生成器和虚表。 | 每项独立 Pass；输出可打印和最小化。 |
| 5.6 | 资源与失败降级 | `CORE/草案` | Drop flags、Result 传播、panic unwind/abort、清理块和 FFI 边界。来源：10、12。 | 各失败策略下析构顺序和 ABI 测试通过。 |
| 5.7 | 分析扩展点 | `EXPERIMENTAL/待决策` | 契约、纯度、effect、污点和合规分析的只读接口。来源：3、8。 | 不改变核心语义；分析失败不得破坏正常编译。 |
| 5.8 | AI/GPU IR 实验 | `EXPERIMENTAL/待决策` | 自动微分、张量形状、计算图、设备放置和 GPU dialect。来源：4。 | 独立 crate/Feature；CPU 对照和数值误差测试。 |
| 5.9 | IR 工具 | `CORE/草案` | verifier、printer、parser、diff、reducer 和 pass tracing。 | 崩溃用例可自动缩减；IR 往返测试通过。 |
| 5.10 | Pass 管线治理 | `CORE/草案` | Pass 顺序、开关、统计、耗时、缓存、回归二分和插件权限。 | 每个 Pass 有负责人、正确性测试和性能基准。 |

### 13.1 P 产品阶段与 G 质量门禁的关系

`P0~P6` 表示产品能力和交付范围；`G0~G6` 表示某项能力能否进入下一阶段的证据门禁，两者不得互相替代。一个 P 阶段可以经过多个 G 门禁，一个 G 门禁也可以检查多个并行工作包。

| 门禁 | 最迟产品阶段 | 必备证据 | 未通过的处理 |
|---|---|---|---|
| G0 语言冻结 | P0/P2 前 | 核心规则接受/否决、形式语义、测试设计 | 保持实验；不得新增稳定语法。 |
| G1 可运行核心 | P1 | LLVM E2E、MIR 验证/解释、核心库 | 停止扩平台，先修端到端链路。 |
| G2 生产工具 | P3/P4 | Vet/Race/Coverage/Profiler/Sanitizer 和 C FFI | 不得使用“生产级”标识。 |
| G3 服务端 | P5 前 | API、韧性、流控、可观测、K8s 压测 | 仅实验发布，无稳定 SLA。 |
| G4 Web 平台 | P5 | JS/DOM/Event Loop/Bundler/SSR 浏览器矩阵 | 不承诺完整 Web 应用支持。 |
| G5 样式与 UI | P5 | Cascade/Flex/Grid/A11y 和跨后端降级 | 不宣称跨平台像素/行为一致。 |
| G6 生态扩展 | P5/P6 | SDK、移动、AI/研究各自 RFC、审计、退出条件 | CORE 禁止反向依赖，独立版本或归档。 |

### 14.1 回归任务卡附加字段

除附录 C 通用字段外，每个复审任务必须增加：`XLF ID`、`复审代码`、`原始价值`、`被拒绝机制`、`最小可用切片`、`稳定晋级条件`、`降级/回退实现`、`连续两里程碑无进展时的重新评审日期`。`CONDITIONAL` 不能只写“等待生态成熟”，必须给出可执行探针和量化 Go/No-Go 条件。

### 14.2 不阻塞主线的实现策略

- 新语义先 Feature Gate 和 Edition 隔离；库/框架能力优先于新关键字。
- 平台能力先单目标端到端，再扩大矩阵；不要求所有后端同步首发。
- 复用 LLVM、WASI、NIST PQC、OpenTelemetry、Skia/FFmpeg、OpenXR、libclang 等成熟标准和实现，并记录依赖许可证/维护风险。
- 高风险运行能力默认关闭、最小权限、可观察、可中止、可回滚；实验工件不得进入 Stable 默认安装。

### 15.1 AI 变更的强制流水线

`任务/权限 → 精选上下文 → 冲突检查 → 计划与最小切片 → 补丁 → 格式/编译/测试 → 五维审查 → 来源/许可证 → 人工或策略批准 → 发布门禁`。任何环节失败必须安全停止、保留工件和给出下一步；禁止通过修改测试、删除断言或改文档来掩盖实现错误。

## 附录 E 基准与性能声明规则

历史材料中诸如函数调用、协程切换、IPC、磁盘读取、JSON 吞吐和冷启动等数字只进入“候选基准”。基准任务必须记录硬件、OS、LLVM/Rust/X 版本、编译参数、输入数据、预热、样本、P50/P95/P99、置信区间、对照版本和复现命令。只有连续发布环境可复现并经过评审的结果，才能进入正式性能基线；仍不得把特定机器结果表述为所有平台保证。
