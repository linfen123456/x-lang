> 大纲版本：1.0-outline｜状态：已冻结结构

## 0. 文档使用规则

### 0.1 文档目标

本大纲将 `docs/原始文档/1.txt` 至 `12.txt` 中连续扩展的构想，重组为可学习、可评审、可实现、可测试的语言文档体系。后续撰写者应按本大纲逐项补齐规范文本、正反例、测试语料和设计依据，不得仅以宣传性描述代替可验证规则。

### 0.2 成熟度与状态

| 成熟度 | 定义 | 进入条件 |
|---|---|---|
| `CORE` | MVP 或 1.0 必需 | 有正式语义、实现计划和一致性测试 |
| `EXTENDED` | 核心稳定后的通用扩展 | 不破坏核心模型，有跨平台降级方案 |
| `EXPERIMENTAL` | 需要 RFC、原型和基准验证 | 明确假设、风险、退出条件和隔离边界 |
| `RESEARCH` | 远期研究方向 | 不阻塞主线，不形成兼容性承诺 |

状态统一使用：`草案`、`待决策`、`已决策`、`原型验证中`、`已验证`、`已稳定`。除“默认决策”明确列出的事项外，本大纲中的语言设计均不得自动视为“已决策”。

### 0.3 章节完成定义

每个主题正式补写时必须包含：章节目标、目标读者、术语、规范性规则、非规范性解释、正确示例、错误示例、边界案例、诊断要求、平台差异、兼容性影响、测试映射、原始资料来源和待决问题。规范性用语统一采用“必须 / 禁止 / 应当 / 可以”。

### 0.4 已接受的文档基线

- 初始实现路线为 Rust + LLVM + 自定义 HIR/MIR；该选择属于实现基线，不要求写入语言可观察语义。
- 核心内存模型采用所有权 + 借用 + RAII；可选 GC 仅作为独立 RFC 的实验项。
- 首批稳定目标为 Windows、Linux、macOS 的 x86_64/ARM64 原生程序。
- AI、Tensor、GUI、全协议栈、ZKP 和自修复能力先进行分层归属评审，不直接纳入核心语法。
- 原始材料中的绝对性能数字均为“待验证目标”，不得作为兼容性或产品承诺。

### 0.5 完整性与追溯要求

本文负责规定“应该写清楚什么”，[原始功能全量追溯矩阵](./X-Lang原始功能全量追溯矩阵.md)负责逐项保存 12 份原始材料中的功能和处置结论，[完整项目目录架构](./X-Lang完整项目目录架构与模块说明.md)负责将功能分配到实际子项目。正式规则必须具有稳定规则 ID，并形成 `XLF 功能 → 规范/RFC → 项目模块 → 测试 → 发布版本` 链路；只有文件级或主题级映射不算完成。

### 0.6 后续专题文档展开方式

当前只保留本语言大纲，原语言规则、教程、标准库、互操作、Web 和样式专题正文已移除。后续补写时按本大纲逐章生成必要专题：学习文档负责教学顺序与可运行示例，规范文档负责规则、正反例、诊断和符合性测试，生态文档负责接口、平台差异和回滚；不得把三类内容重新堆入同一个超大文件。
