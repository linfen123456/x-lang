# X-Lang 运行运维与可靠性

运行手册把“可运行”定义为可观测、可降级、可回滚、可恢复。每项服务、编译器流水线和注册表都有 Owner、备份值班、SLI/SLO、告警、Runbook、数据分类、RTO/RPO 和演练记录。

所有日志/Trace/Core/AI 上下文默认脱敏；关联 `run_id/trace_id/change_id`，但不得记录 Token、密钥、完整个人数据或未经授权的源代码。

## 运维对象与责任边界

运维对象不仅包括在线服务，还包括包注册表、文档站、构建与发布基础设施、制品镜像、崩溃收集端和兼容性测试设备。离线编译器默认不依赖遥测服务；远端缓存、注册表和 AI 能力不可用时，核心本地构建仍应给出确定错误或使用已验证的离线缓存。

每个对象必须维护下列信息：主 Owner、备份 Owner、用户影响、依赖、数据分类、容量上限、健康检查、SLI/SLO、告警阈值、常见故障、停止与恢复步骤、RTO/RPO、升级和回滚方法。尚未上线的对象明确标记为规划，不产生虚构运行指标。

## SLI、SLO 与错误预算

| 对象 | 建议 SLI | SLO 关注点 | 不得掩盖的问题 |
|---|---|---|---|
| 包注册表 | 成功请求率、发布完整性、读取延迟 | 可用性、不可篡改、区域恢复 | 哈希不一致、恶意包、版本覆盖 |
| 远端构建/缓存 | 正确命中率、构建成功率、端到端时延 | 正确性优先于命中率 | 错误缓存、跨租户泄漏、不可复现结果 |
| 文档与下载站 | 可用性、下载校验成功率 | 安装入口可达、版本信息一致 | 过期安装器、错误签名或镜像漂移 |
| 崩溃收集 | 有效事件率、脱敏成功率、处理延迟 | 不丢关键趋势且不泄露源码/秘密 | 重复风暴、隐私数据、伪造事件 |
| 发布流水线 | 候选成功率、回滚耗时、制品一致性 | 可审计、可撤销、可恢复 | 未签名制品、部分平台版本错配 |

错误预算耗尽时暂停高风险发布和非必要变更，优先修复可靠性。不得通过降低监控采样、扩大成功定义或关闭告警恢复预算。

## 告警与事件生命周期

告警必须指向用户影响或明确的先行信号，包含服务、环境、版本、症状、阈值、看板和 Runbook。事件按严重度分级：数据或供应链完整性、广泛不可用和无法回滚属于最高等级；单个平台实验能力失败不能自动升级为全项目最高等级。

事件流程为发现、确认、指挥、止损、恢复、验证、沟通和复盘。事件指挥者负责决策节奏，技术负责人负责诊断，沟通负责人向用户说明影响和进展。恢复后必须验证数据、签名、版本、缓存和客户端升级路径，不能以“进程已启动”作为恢复完成。

## 降级、回滚与灾难恢复

优先使用停止新写入、切换只读、禁用实验 Feature、绕过远端缓存、回退镜像等可逆操作。涉及包版本、签名或依赖元数据时，禁止静默覆盖已发布内容；通过撤销标记、修订版本和安全公告处理。数据库或注册表恢复必须先在隔离环境验证一致性，再切换生产流量。

灾难恢复演练至少覆盖控制面不可用、对象存储损坏、密钥泄露、恶意包、错误大规模发布和区域故障。演练记录包括假设、时间线、实际 RTO/RPO、缺口、负责人和整改期限。

## 验收标准

- 每个计划上线的服务都有可执行 Runbook，而不是只有架构描述。
- 告警能定位到版本与变更，并有明确停止条件和升级路径。
- 回滚演练验证客户端、服务端、数据和制品四个层面的一致性。
- 日志、Trace、Core dump 和 AI 上下文通过抽样证明脱敏与权限策略有效。
