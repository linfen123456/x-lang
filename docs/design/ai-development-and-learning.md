# AI 应用、协作与学习实现设计

> 状态：Proposed｜日期：2026-09-29｜依据：日常开发与 AI 协作风险大纲 `XLE-AI-001～020`、工程大纲第十五篇。
> 范围：P3+ 工具和 SDK；不把模型输出、自然语言或训练图加入 X 1.0 编译语义。

## 1. 应用 SDK 的最小公开边界

提供可替换的 Provider Adapter，业务侧调用显式的请求与流式响应接口：输入/输出类型、结构化结果校验、超时、取消、token/费用/内存预算、速率限制、可重试条件与错误类型由 SDK 契约定义。所有模型响应均为不可信数据；结构化结果必须验证，再交业务层使用。密钥只经宿主秘密存储注入；日志、Trace、报错和上下文包均不得泄漏原始凭据或个人数据。网络与模型不可用时返回可处理的错误，不吞错或自动提权。

## 2. AI 编码闭环与威胁边界

`任务/授权 → 最小上下文（规范/源码/测试/版本） → 提议 diff → 编译与符合性 → 安全/来源审查 → 人工或策略批准 → 发布`。

语义索引与 Rule ID 必须指向真实版本的符号和规则；外部网页、Issue、依赖配置与模型建议是数据，不能修改指令优先级。工具按目录、命令、网络、秘密与资源预算最小授权；越权请求和工作区重叠改动均阻断并审计。红队夹具覆盖提示注入、幻觉 API、破坏测试以伪造通过、越权工具调用、日志泄密、模型故障和并发补丁冲突。不得把“AI 生成”当作正确性证据。

## 3. 学习与训练边界

学习产品使用版本化可运行教程、正反例、诊断解释及修复建议；以新手在同任务上的完成率、耗时、错误修复率衡量，不以主观“易学”宣传代替对照。模型训练仍属独立 P5+ 研究/生态：优先与成熟张量库、设备后端和外部训练系统互操作；自动微分、分布式或 GPU 特性需分别通过 RFC/ADR、正确性及能耗/吞吐基准，不改变核心默认语义。

## 4. 交付门禁

P3 首交 Provider Adapter 和一项可运行推理服务示例、离线/失败注入与安全夹具；AI 协作工具先只读索引，再逐步开放可审核补丁权限。每次晋级报告版本、支持的 Provider、数据保留、成本、故障率、误报/漏报、安全评审和撤回方案。任何供应商变更不应影响 X 编译结果；未完成隐私/安全评审不得发布。
