# RFC-0007：所有权、借用、移动与 Drop

> 状态：Proposed
> 日期：2026-08-18
> 目标版本：X-Lang 1.0 候选
> 依赖：RFC-0006
> 相关缺口：`GAP-LANG-04`、`GAP-LANG-05`
> 正式产物：接受后生成 `specs/language/ownership-and-drop.md`。

## 1. 绑定与传递

- `let` 创建不可重新赋值绑定，`var` 创建可重新赋值绑定；二者不形成不同所有权类型；
- `Copy` 值按值使用时复制，非 `Copy` 值按值使用时移动；
- 共享借用写作 `&place`，独占借用写作 `&mut place`；
- 不要求每次声明额外写 `move/borrow/copy`；`move` 关键字只改变闭包捕获；
- API 通过参数和返回类型表达拥有、共享借用和独占借用。

## 2. 借用

- 任一时刻允许多个共享借用，或一个独占借用，不能并存冲突别名；
- 重借用不能扩大权限或超过来源生命周期；
- 返回借用值必须能唯一绑定到输入借用或静态存储，不能指向局部值或已销毁 Temporary；
- 索引和字段借用继承其基础 Place 的来源；编译器仅在静态证明投影不重叠时允许多个独占字段借用；
- 借用终点由控制流上的最后使用推导，但 NLL 不得改变可观察 Drop 顺序。

## 3. 初始化、移动与赋值

- MIR 为每个可移动 Place/字段记录初始化状态；未初始化读取和二次移动报错；
- 部分移动后不能整体读取或移动原值，但可以访问仍初始化且未借用的字段；
- 具有用户 `Drop` 实现的类型禁止部分移动，必须借用或调用显式分解 API；
- 覆盖已初始化 Place 前先保存新值求值结果，再析构旧值，再写入；任一步失败不能双重 Drop；
- 返回值在调用者目标位置构造；返回借用必须通过生命周期约束。

## 4. Drop 顺序

- 局部绑定按成功初始化的逆序析构；
- 结构体字段按声明逆序析构，tuple/数组元素按索引逆序析构；
- 仅析构仍处于已初始化状态的字段，且恰好一次；
- 正常退出、`return`、`break`、`?` 和允许 unwind 的 panic 均沿退出路径执行清理；
- abort、进程强杀或无法恢复的 OOM 不承诺运行用户 Drop；具体终止规则由 RFC-0008 定义；
- Drop 期间再次 panic 的策略必须由运行时配置固定，不能跨越 C ABI。

## 5. 诊断和验收

`X-E4xxx` 用于移动、借用和 Drop；Rule ID 使用 `RULE-OWN-*`、`RULE-DROP-*`。

- compile-pass：移动、共享/独占借用、重借用、无冲突字段借用和合法返回借用；
- compile-fail：use-after-move、二次移动、冲突借用、局部引用逃逸、Drop 类型部分移动；
- MIR Snapshot：字段级 init/move/drop flags；
- run-pass：正常、提前返回、`?` 和 unwind 的精确 Drop Trace；
- 属性测试：任意控制流下每个已初始化资源至多析构一次。
