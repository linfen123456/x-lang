# XUI 与多平台适配实现设计

> 状态：Proposed｜日期：2026-09-29｜依据：[RFC-0011](../../rfcs/0011-xui-typed-declarative-and-platform-capabilities.md)、工程大纲 P3–P5+、目录架构 §1.5。
> 责任：P3+ 联邦生态；不得成为 P0/P1 核心 Workspace 成员或读取编译器私有 IR。

## 1. 分层与数据流

```
X 业务状态/消息（普通类型和函数）
  → XUI 类型化 View → 公共 UI IR（版本化 + 能力/无障碍标注）
  → 目标验证器（缺失能力报错或显式降级）
  → Web DOM/SSR + CSS Modules | Desktop Host | Mobile Host | WeChat Miniapp
  ↔ 宿主事件/权限/生命周期桥 → 类型化 Message → 业务状态
```

核心编译器只提供经批准的语言语义、稳定诊断与公开构建/接口；XUI 生态包通过公开协议获取输入。P3 先实现单向静态 View 与显式事件、状态更新，再增加导航、资源、离线；不在一次提交中建立全能 UI 框架。UiIr 的公开版本/向后兼容策略经 RFC-0011 接受后锁定。样式在 Web 由浏览器的 CSS 负责；不复制 CSS 布局算法。

## 2. 宿主矩阵与失败策略

| 阶段 / 宿主 | 交付路径 | 必需门禁 | 未满足时 |
|---|---|---|---|
| P3 Web/WASI 探针 | 共享业务逻辑经 WASI/组件接口探针；Web DOM/SSR 适配 | 可运行表单、列表、状态消息；组件边界与序列化可复现 | 保留显式 JS 宿主桥，WASM 不作强制前置 |
| P4 Web 产品样例 | CSS Modules、资源、导航、离线策略和可访问性 | 跨浏览器功能、键盘/屏幕阅读器、SSR/水合、错误恢复、包体/延迟基线 | 功能标记实验，不声称稳定 Web 平台 |
| P5+ 桌面 | 受控宿主壳 + UI IR 适配 | Windows/macOS/Linux 分别验收安装、无障碍、权限、生命周期 | 各 OS 独立标记支持等级 |
| P5+ 移动 | Android/iOS 平台宿主桥和 UI 映射 | 真机、后台/恢复、权限、无障碍、包体、电量及上架 | 单独阻断该设备/OS 目标 |
| P5+ 微信小程序 | 模板/样式/逻辑生成与宿主 API 桥 | 官方工具出包、真机、网络/存储权限、离线/审核路径 | 不声明支持；不预设 WASM 可用 |

其他小程序平台在微信适配通过后另开目标矩阵和适配评审。平台特有能力使用显式类型化扩展；必需能力缺失则构建失败，可选能力必须有调用者提供的替代路径。外观按平台适配，只要求状态、事件和业务行为的可测试语义一致。

## 3. 纵向样例与团队边界

首个跨平台黄金项目为含表单、列表和离线状态的业务 UI；同一领域逻辑在 API 服务端与 UI 端复用，记录权限拒绝、无网络、重启恢复、无障碍及宿主生命周期反例。Web/WASI 与 XUI 组可在稳定业务/消息/IR 接口后并行；桌面/移动/微信组从相同公开契约派生，不能要求核心语言为单一平台特例增加关键字。

准入顺序：RFC-0011 Proposed → UI IR/能力验证原型 → Web 真正应用及失败样例 → 接受/修订 RFC → 按宿主单独晋级。若平台映射无法忠实保留行为，显式不支持；若收益不足，维持独立生态而非扩核心语法。
