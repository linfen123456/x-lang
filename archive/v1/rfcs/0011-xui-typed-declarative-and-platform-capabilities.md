# RFC-0011：XUI 类型化声明式接口与跨平台能力契约

> 状态：Proposed｜日期：2026-09-29
> 类型：P3+ 独立生态接口提案；不是 X-Lang 1.0 核心语法，也不覆盖已批准语言 RFC。
> 依赖：稳定的 X 类型、包、构建与公开宿主接口；实施设计见 [XUI 与平台适配](../docs/design/xui-and-platforms.md)。

## 1. 目标与非目标

以普通 X 类型和函数编写声明式 UI，编译/转换为不同宿主的 UI 表达；跨目标承诺状态、事件、导航、资源及无障碍语义一致，不承诺像素一致、所有宿主 API 等价或“一次编写无需调试”。不新增 UI 关键字、第二套类型系统或核心编译器必须依赖的 UI crate。首次目标为 Web；桌面、移动、微信小程序分别晋级。

## 2. 公共契约候选

- `View<State, Message>`：由纯视图函数从当前状态构造类型化树；业务状态通过显式消息更新，渲染器不拥有业务真相。
- `Event<Message>`：目标控件发出有类型的消息；事件顺序、生命周期和取消由适配器文档定义，不能假装各宿主完全相同。
- `UiIr { version, nodes, bindings, resources, capabilities }`：版本化的生态侧中间契约；稳定语义和可访问性标注可检查，平台专属字段显式命名空间化；不暴露 compiler 私有 AST/HIR/MIR。
- `Capability<Target>`：应用声明必需/可选宿主能力。缺少必需能力则目标构建失败；可选能力仅在调用者提供显式替代路径时降级，不得静默忽略。
- 宿主桥只接收经检查的事件与资源句柄；外部数据在信任边界验证，权限按宿主策略申请，秘密不写入 UI IR。

接口名称和序列化形状均为候选；在 P3 原型及版本化夹具通过前不得称为稳定 API。

## 3. 渲染与样式边界

Web 使用 DOM/SSR 与标准 CSS/CSS Modules；核心样式仅表达跨目标可验证的 Token、类型化值和受限 CoreStyle IR。桌面/移动先使用宿主壳及平台适配器，不默认自研统一布局或自绘引擎。小程序生成目标模板/样式/逻辑工件，经官方工具、真机和审核链路验证；WASM 仅在目标宿主探针证明可用时采用。

## 4. 兼容性与晋级

UiIr 版本与适配器支持矩阵独立发布；新版本不得无迁移地改变旧消息/状态语义。P3 原型至少验证静态页、交互表单、导航和资源失败；P4 Web 完整样例；P5+ 每个桌面/移动/微信目标独立通过无障碍、性能、离线、权限、生命周期和打包/发布测试。任一宿主失败只阻断该宿主等级，不改变核心语言。

## 5. 评审前必须关闭

| 问题 | Owner 角色 | 最迟阶段 | 失败回退 |
|---|---|---|---|
| 状态与异步事件顺序 | XUI + Runtime Owners | P3 原型前 | 限制为同步消息和显式宿主任务 |
| UI IR 版本及迁移 | XUI + Platform Owners | P4 Web 发布前 | 保持实验版本，不对外承诺稳定 |
| 无障碍核心属性最小集 | Accessibility + Web Owners | P4 Web 门禁前 | 缺能力时报错，不发布对应组件 |
| 首个微信宿主限制与审核 | Miniapp Owner | P5+ 适配开始前 | 只发布 Web，不声称微信支持 |

接受条件：语言、平台、无障碍和安全审查；每个公共规则有正反例、目标适配差异清单及可运行验证样例；接受不等于实现。
